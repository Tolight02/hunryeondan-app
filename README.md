# 훈련단 수료 D-day + 오늘 식단

한 번 설정만 해두면, 신분(훈련병/조교/특기학교/후보생)에 맞는 식단을 볼 수 있는 화면입니다.
훈련병은 기수 또는 입소일을 넣으면 **D-day + 진행률(%)**도 같이 보여줘요.

로그인, 회원가입 없음. 어머님 같은 분들도 그냥 열어서 신분 하나 고르고 끝.

## 신분별 구조

처음 들어가면 신분을 선택해요: **훈련병 / 조교 / 특기학교 및 진주 자대 / 부사관 및 장교 후보생**.
신분마다 보는 식당과 간편식 종류가 달라요 (`server.js`의 `CATEGORY_CONFIG`에서 관리):

| 신분 | 식당 | 간편식 |
|---|---|---|
| 훈련병 | 공군교육사령부훈련단 (한식만, 일품/간편식 제외) | 없음 |
| 조교 | 공군교육사령부훈련단 | 마이보글 / T·O / 로카프랩 |
| 특기학교 및 진주 자대 | 공군교육사령부정통학교 | T/O(B) / T/O(A) / 셀프라면 |
| 부사관 및 장교 후보생 | 공군교육사령부후보생 | 마이보글 / T·O / 로카프랩 (추정치, 확인 필요) |

훈련병만 기수/입소일을 입력해서 수료 D-day를 볼 수 있고, 나머지 신분은 바로 식단 화면으로 가요.
훈련병도 "모르겠어요"를 선택하면 D-day 없이 바로 식단만 봐요.

## 이걸 켜두는 사람(관리자, 1명)이 할 일

### 1. 설치
```bash
cd hunryeondan-app
export GITHUB_TOKEN=본인_깃허브_토큰   # read:packages 권한만 있으면 됨
npm install
cp .env.example .env
```

`.env`에 본인(관리자)의 웰스토리플러스 아이디/비밀번호를 넣어주세요.
**이 계정은 관리자 것 하나만 있으면 되고, 사용하는 모든 사람이 로그인할 필요는 없습니다.**

### 2. 기수 표 (`data/cohorts.json`) — 875~886기까지는 이미 정확하게 채워져 있음

병무청이 공개한 "2026년도 공군 병 연간 모집일정" PDF 기준으로 875기(2026년 1월 입영)부터
886기(2026년 12월 입영)까지 정확한 입영일/수료일을 이미 넣어뒀습니다.

887기 이후(2027년 이후) 새 일정이 나오면, 병무청에서 같은 형식의 PDF를 받아서
(또는 저에게 다시 올려주시면) 아래 형식으로 한 줄만 추가하면 됩니다:

```json
{ "gigsu": 887, "enlistDate": "2027-01-18", "completionDate": "2027-02-19" }
```

표에 없는 기수를 고르면, 자동으로 "입영일+32일"로 대략 계산해서라도 보여줍니다
(875~886기 실측 패턴 기준 추정치이며, 정확하진 않지만 일단 작동은 합니다).

### 3. 실행
```bash
npm start
```
`http://localhost:3000` — 이 주소를 계속 열어두려면 Render.com이나 Railway.app 같은
무료/저가 호스팅에 올려서 24시간 켜두는 걸 추천해요.

## 어머님/사용자들이 할 일

그냥 그 주소로 들어가서 → 기수 선택 (또는 입소일 선택) → 확인 누르기.
한 번 하면 그 폰에 저장돼서 다음부턴 앱 켜자마자 바로 D-day가 보여요.

## 메뉴 사진/상세메뉴/영양성분/간편식이 안 보인다면

**(2026-08-01 확인, 최종) 서버는 라이브러리의 `getMenus()`를 거치지 않고 원본 `/api/meal`을
직접 불러와요.** 라이브러리가 자체적으로 매핑하면서 `courseTxt`(브랜드/분류 텍스트, 예: "한식"/
"마이보글"/"로카프랩")와 `subMenuTxt`(반찬 목록 텍스트)를 버리길래, 원본 데이터를 직접 그룹핑해서
이 두 필드를 살려뒀어요. 간편식 구분은 이제 `courseTxt` 텍스트를 직접 비교해서 판별하기 때문에
(코드 추측이 아니라서) 훨씬 안정적이에요. `courseType`(AA/EE/DD 같은 코드) 매핑은 혹시 몰라 보조
수단으로 남겨뒀어요.

이 구조가 나중에 바뀔 수도 있어요. 그런 경우:

1. 서버 켜놓은 상태에서 브라우저로 `localhost:3000/api/menu` 접속
2. 나오는 텍스트(JSON)를 복사해서 저한테 붙여넣어주세요
3. 실제 필드 이름에 맞게 `public/index.html`의 `NAME_KEYS` / `IMAGE_KEYS` / `KCAL_KEYS` /
   `DETAIL_KEYS` / `NUTRI_CANDIDATES` 부분을 바로 고쳐드릴게요

(영양성분 모달은 인식 못한 필드도 일단 다 나열은 해주니, 완전히 안 보이진 않을 거예요.)

**간편식(마이보글/T·O/로카프랩) 구분은 이제 `courseTxt` 텍스트로 직접 판별해서 코드 추측이 필요
없어요.** `courseType` 코드 매핑(`COURSE_TYPE_BRAND_MAP`)은 혹시 `courseTxt`가 없는 경우를 대비한
보조 수단으로만 남겨뒀어요.

## 2027년, 2028년에도 계속 쓰려면 (유지보수)

**앱을 다시 만들 필요는 없습니다.** 병무청이 새 연간 일정을 발표할 때마다
아래 3단계만 반복하면 돼요:

1. 병무청 누리집(군지원안내 → 이달의 모집계획 → 공군 모집계획)에서 새 PDF를 열어서
   표 전체를 복사 (Ctrl+A, Ctrl+C)
2. 메모장 등에 붙여넣고 텍스트 파일로 저장 (예: `schedule-2027.txt`)
3. 아래 명령 실행:

```bash
node scripts/import-schedule.js schedule-2027.txt
```

새 기수들이 `data/cohorts.json`에 자동으로 추가되고, 서버를 재시작하면
(`npm start`) 바로 반영됩니다. 기존 기수 데이터는 그대로 남고, 겹치는 기수만 새 값으로 덮어써요.

PDF의 표 형식 자체가 바뀌어서 스크립트가 제대로 못 읽으면, 그 PDF나 복사한 텍스트를
저에게 다시 올려주세요 — 스크립트를 새 형식에 맞게 고쳐드릴게요.
